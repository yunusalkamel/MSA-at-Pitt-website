# Reporting and recovery

## Preview acceptance

Open the draft branch URL with a Vercel-authenticated browser. In the preview editor publish a small change, open History, preview the version, restore a field, and restore the previous state. In the owner dashboard create a snapshot and export the website. The JSON includes published Sanity page documents, gallery and image metadata, and inline fields. Image files stay at their existing asset URLs. Snapshot restoration acts on the inline editor content. Changes made directly in Sanity Studio, calendar feeds and calculated prayer times have their own source of truth.

The server writes compressed, encrypted before/after records and the live editor document in one revision-guarded Sanity transaction. The version contains its author, time and source restore ID. A separate Supabase activity feed can lag if logging fails. The Sanity version history is authoritative. Preserve the environment's MSA_MANAGEMENT_KEY in secure recovery storage, since it also protects version history. Losing or replacing that key affects access to old encrypted versions. Existing content receives its first recoverable previous state on the next publication.

## Optional services

1. Create a Google Analytics 4 web stream with advertising personalization and Google Signals disabled. Disable automatic enhanced measurement for this stream. Copy its G- measurement ID to **GA4_MEASUREMENT_ID**. In the stream's Measurement Protocol API secrets section create a secret and put it in **GA4_API_SECRET**. Both variables are server-only. Register **msa_event** and **msa_screen** as event-scoped custom dimensions. Event and story identifiers are the first 16 hexadecimal characters of SHA-256 of the public calendar event ID or story slug.
2. Enable the Google Analytics Data API in Google Cloud. Create a service account, grant its email Viewer on the GA4 property and set **GA4_SERVICE_ACCOUNT_JSON** to the service-account JSON as a sensitive server-only variable. Set **GA4_PROPERTY_ID** to the numeric property ID. Configure separate preview reporting credentials/property if needed. Never assign the production-property credentials to preview.
3. Set **VITE_OPTIONAL_ANALYTICS=true** on Production to expose the footer consent control. In Owner, open Analytics → Analytics providers → Load collection settings → Enable Google Analytics 4. Allow up to 15 seconds for changes to reach a warm server. Optional collection is off by default. It runs after idle and opt-in, using a random browser identifier, broad device information and approved page/event names. Only named acquisition sources are forwarded. For campaign attribution, put identical comma-separated public campaign names in **VITE_ANALYTICS_CAMPAIGNS** and **GA4_CAMPAIGNS**. The browser and server both check this list. Server-side Measurement Protocol has different session and acquisition coverage from a full browser tag. Treat sparse audience, exit, and attribution fields as unavailable.
4. Enable Chrome UX Report API and Chrome UX Report History API in Google Cloud. Restrict an API key to these APIs and store it as **CRUX_API_KEY** on Production. Load Performance and select a page or the whole site. Chrome returns rolling real-user 75th-percentile measurements where its sample threshold is met. Low-volume pages may have no series. Vercel Speed Insights and PageSpeed links provide additional diagnostics.
5. Clarity tracking uses project **zjhbwa68n4** by default. Set **VITE_CLARITY_PROJECT_ID** only for an intentional project change. The recorder runs on eligible public production pages after a separate opt-in and after the page renders. Keep the project’s strict masking enabled. In Owner, use the separate Clarity toggle and open Heatmaps or Recordings to observe consented visits. To show aggregate friction counts inside Owner, add the project’s sensitive **CLARITY_EXPORT_TOKEN** under Vercel Environment Variables.
6. Redeploy a preview after changing preview variables. Confirm the owner's reports distinguish missing credentials, empty data and quota errors. After review, set the production variables and enable analytics only if desired. The preview never sends live analytics events. See [Google collection documentation](https://developers.google.com/analytics/devguides/collection/protocol/ga4/reference), [GA4 reporting](https://developers.google.com/analytics/devguides/reporting/data/v1/api-schema) and [Chrome UX Report](https://developer.chrome.com/docs/crux/history-api).

## Production release

- Confirm the preview owner and a separate authorized administrator can publish and restore. Revoke administrator access with an existing session and verify subsequent write and private reporting requests are denied.
- Verify a backup export and retain the management encryption key. Confirm the Sanity token can create private version documents and read the correct dataset.
- Review the mobile performance report. Run the protected preview on a real iPhone with the owner's session and check the calendar, chart, gallery, drag-and-drop image replacement and restore workflow.
- Review the draft PR and deployment-scoped variables, then authorize production rollout. Review real-user mobile LCP, INP and CLS after enough traffic has accumulated.
